# 文章点赞功能修复说明

## 🐛 问题描述

1. **点赞计数变负数**: 取消点赞后，点赞数可能变成负数
2. **重复点赞问题**: 第一次点赞+1，第二次取消-1，第三次应该+1，但实际可能出现异常
3. **缺少定时同步**: 点赞数据没有从Redis定时同步到MySQL

## 🔍 问题原因

### 原来的逻辑问题

1. **没有处理重新点赞**:
```java
// 只查询 isDelete = 0 的记录
wrapper.eq("isDelete", 0);
// 如果之前取消过点赞（isDelete = 1），再次点赞会插入新记录
```

2. **Redis计数可能为负**:
```java
// 直接使用 increment，可能导致负数
stringRedisTemplate.opsForValue().increment(countKey, -1);
// 如果Redis中没有初始值或值为0，减1会变成-1
```

3. **缺少同步任务**:
- 只同步了图案（Pattern）的点赞
- 没有同步文章（Article）的点赞

## ✅ 修复方案

### 1. 修复点赞逻辑（ArticleServiceImpl.java）

**修改要点**:

#### a. 查询所有点赞记录（不限制isDelete）

```java
// 修改前
wrapper.eq("articleId", articleId)
       .eq("userId", userId)
       .eq("isDelete", 0);  // ❌ 只查询未删除的

// 修改后
wrapper.eq("articleId", articleId)
       .eq("userId", userId);  // ✅ 查询所有记录
```

#### b. 处理三种情况

```java
if (existLike != null && existLike.getIsDelete() == 0) {
    // 情况1：已点赞 -> 取消点赞
    existLike.setIsDelete(1);
    articleLikeMapper.updateById(existLike);
    newLikeStatus = false;
    likeChange = -1;
    
} else if (existLike != null && existLike.getIsDelete() == 1) {
    // 情况2：之前取消过 -> 重新点赞 ✅ 新增
    existLike.setIsDelete(0);
    articleLikeMapper.updateById(existLike);
    newLikeStatus = true;
    likeChange = 1;
    
} else {
    // 情况3：首次点赞
    articleLikeMapper.insert(like);
    newLikeStatus = true;
    likeChange = 1;
}
```

#### c. 防止Redis计数变负数

```java
// 先获取当前Redis中的值
String countStr = stringRedisTemplate.opsForValue().get(countKey);
if (countStr != null) {
    long count = Long.parseLong(countStr);
    // 如果是取消点赞且当前计数>0，才减1 ✅
    if (likeChange == -1 && count > 0) {
        currentCount = stringRedisTemplate.opsForValue().increment(countKey, -1);
    } else if (likeChange == 1) {
        currentCount = stringRedisTemplate.opsForValue().increment(countKey, 1);
    } else {
        currentCount = count;  // 已经是0，不再减少
    }
} else {
    // Redis中没有值，从数据库获取并设置
    int dbCount = article.getLikeCount() != null ? article.getLikeCount() : 0;
    int newCount = Math.max(0, dbCount + likeChange);  // ✅ 确保不为负
    stringRedisTemplate.opsForValue().set(countKey, String.valueOf(newCount));
    currentCount = (long) newCount;
}
```

### 2. 添加文章点赞同步任务（LikeSyncTask.java）

**新增方法**: `syncArticleLikeCounts()`

```java
/**
 * 同步文章点赞数据到数据库
 */
private void syncArticleLikeCounts() {
    // 1. 获取所有文章点赞计数的Redis key
    Set<String> countKeys = stringRedisTemplate.keys(ARTICLE_LIKE_COUNT_KEY_PREFIX + "*");
    
    // 2. 遍历每个key
    for (String countKey : countKeys) {
        // 提取文章ID
        Long articleId = Long.parseLong(articleIdStr);
        
        // 获取Redis中的点赞数
        String countStr = stringRedisTemplate.opsForValue().get(countKey);
        int likeCount = Integer.parseInt(countStr);
        
        // 3. 直接更新数据库（覆盖式更新，因为Redis是最新值）
        articleMapper.updateById(new Article() {{
            setId(articleId);
            setLikeCount(likeCount);
        }});
    }
}
```

**在定时任务中调用**:

```java
@Scheduled(fixedRate = 1 * 60 * 1000) // 每1分钟
@Transactional
public void syncLikeDataToMySQL() {
    // 1. 同步图案点赞计数
    syncLikeCounts();
    
    // 2. 同步图案用户点赞关系
    syncUserLikeRelations();
    
    // 3. 同步文章浏览量
    syncArticleViewCounts();
    
    // 4. 同步文章点赞数据 ✅ 新增
    syncArticleLikeCounts();
}
```

## 🔄 完整工作流程

### 用户点赞操作

```
第一次点击（点赞）:
  1. 检查数据库 -> 无记录
  2. 插入点赞记录（isDelete=0）
  3. Redis计数 +1
  4. 数据库计数 +1
  5. 返回: { liked: true, likeCount: 101 }

第二次点击（取消）:
  1. 检查数据库 -> 有记录且isDelete=0
  2. 更新记录（isDelete=1）
  3. Redis计数 -1（检查>0才减）
  4. 数据库计数 -1
  5. 返回: { liked: false, likeCount: 100 }

第三次点击（重新点赞）:
  1. 检查数据库 -> 有记录且isDelete=1 ✅
  2. 更新记录（isDelete=0）✅
  3. Redis计数 +1
  4. 数据库计数 +1
  5. 返回: { liked: true, likeCount: 101 }
```

### 定时同步任务

```
每1分钟执行一次:
  1. 扫描 Redis: article:like:count:*
  2. 读取每个文章的点赞数
  3. 更新到MySQL数据库
  4. 保持数据一致性
```

## 🔧 防止负数的机制

### 1. Redis层面

```java
// 取消点赞时检查当前值
if (likeChange == -1 && count > 0) {
    // 只有当前值>0时才减1
    currentCount = stringRedisTemplate.opsForValue().increment(countKey, -1);
} else if (likeChange == -1 && count == 0) {
    // 已经是0，不再减少
    currentCount = 0L;
}
```

### 2. 数据库层面

```java
// 使用 Math.max 确保不为负
int newCount = Math.max(0, dbCount + likeChange);
```

### 3. 同步层面

```java
// 定时同步时，Redis的值是准确的
// 直接覆盖数据库的值，而不是增量更新
articleMapper.updateById(new Article() {{
    setId(articleId);
    setLikeCount(likeCount);  // 直接设置，不是 +=
}});
```

## ⚠️ 注意事项

### 1. Redis持久化

建议开启Redis的AOF持久化，防止Redis重启导致点赞数据丢失：

```conf
# redis.conf
appendonly yes
appendfsync everysec
```

### 2. 并发控制

使用数据库事务保证原子性：

```java
@Transactional(rollbackFor = Exception.class)
public LikeResult likeArticle(Long articleId, Long userId) {
    // 事务保证数据一致性
}
```

### 3. 同步频率

当前设置为1分钟同步一次（测试用），生产环境建议5分钟：

```java
@Scheduled(fixedRate = 5 * 60 * 1000) // 5分钟
```
