### 测试场景2：验证数据正确性

在 MySQL 中执行：

```sql
-- 查看评论层级结构
SELECT 
    id,
    parentId,
    rootId,
    replyToUserId,
    content,
    CASE 
        WHEN parentId IS NULL THEN '主评论'
        ELSE CONCAT('回复（rootId=', rootId, '）')
    END as commentType
FROM comment
WHERE isDelete = 0
ORDER BY COALESCE(rootId, id), createTime;
```

**预期结果**：

| id | parentId | rootId | replyToUserId | content | commentType |
|----|----------|--------|---------------|---------|-------------|
| 1001 | NULL | NULL | NULL | 这是一条主评论... | 主评论 |
| 1002 | 1001 | 1001 | 用户1ID | 这是二级回复 | 回复（rootId=1001） |
| 1003 | 1002 | 1001 | 用户2ID | 这是三级回复 | 回复（rootId=1001） |
| 1004 | 1003 | 1001 | 用户3ID | 这是四级回复 | 回复（rootId=1001） |

**关键验证点**：
- ✅ 所有回复的 `rootId` 都指向主评论的 `id`
- ✅ `parentId` 指向直接父评论
- ✅ `replyToUserId` 指向被回复的用户ID

## 🐛 常见问题

### Q1: 数据库升级失败

**症状**：执行 SQL 脚本时报错

**解决方案**：
```sql
-- 检查字段是否已存在
DESC comment;

-- 如果字段已存在，跳过添加字段的步骤
-- 只执行数据迁移部分
```

### Q2: 前端不显示 @用户名

**症状**：回复中没有显示 `@用户名`

**可能原因**：
1. 后端没有返回 `replyToUserName` 字段
2. 前端组件没有更新

**解决方案**：
```bash
# 1. 检查后端日志
# 2. 清空浏览器缓存
# 3. 重启前端服务
cd clothingPattern-front
npm run dev
```

### Q3: 回复数统计不正确

**症状**：主评论的回复数与实际不符

**解决方案**：
```sql
-- 手动修复回复数
UPDATE comment c1
SET c1.replyCount = (
    SELECT COUNT(*) 
    FROM comment c2 
    WHERE c2.rootId = c1.id 
    AND c2.isDelete = 0 
    AND c2.auditStatus = 'APPROVED'
)
WHERE c1.parentId IS NULL;
```

### Q4: 性能问题

**症状**：评论加载缓慢

**解决方案**：
```sql
-- 检查索引是否存在
SHOW INDEX FROM comment;

-- 如果没有 idx_rootId 索引，手动创建
ALTER TABLE comment ADD INDEX idx_rootId (rootId);

-- 分析查询性能
EXPLAIN SELECT * FROM comment WHERE rootId = 1001;
```

### 查询性能

```sql
-- 测试查询性能
SET profiling = 1;

SELECT c.*, u.userName, u.userAvatar, u2.userName as replyToUserName 
FROM comment c 
LEFT JOIN user u ON c.userId = u.id 
LEFT JOIN user u2 ON c.replyToUserId = u2.id
```
