# 收藏功能修复说明

## 🐛 问题描述

1. **重复收藏报错**: 已收藏的文章再次点击收藏按钮时报错"已收藏该文章"
2. **无法取消收藏**: 需要调用单独的取消收藏接口
3. **缺少收藏数显示**: 前端无法获取文章的收藏总数

## 🔍 问题原因

原来的收藏逻辑：
- `POST /article/collect` - 只能收藏，已收藏则报错
- `POST /article/collect/cancel` - 只能取消收藏，未收藏则报错
- 返回值只有 `boolean`，没有收藏总数

这种设计需要前端：
1. 先判断收藏状态
2. 根据状态调用不同的接口
3. 单独查询收藏数

## ✅ 修复方案

### 1. 创建 CollectResult 返回对象

**新建文件**: `CollectResult.java`

### 2. 修改收藏逻辑为切换模式（Toggle）

**修改文件**: `ArticleServiceImpl.java`

**原逻辑**:
```java
public boolean collectArticle(Long articleId, Long userId) {
    // 检查是否已收藏
    if (existCollect != null) {
        throw new BusinessException("已收藏该文章"); // ❌ 报错
    }
    // 添加收藏
    return true;
}
```

**新逻辑**:
```java
public CollectResult collectArticle(Long articleId, Long userId) {
    // 检查收藏状态
    if (existCollect != null && existCollect.getIsDelete() == 0) {
        // 已收藏 -> 取消收藏 ✅
        existCollect.setIsDelete(1);
        articleCollectMapper.updateById(existCollect);
        collectChange = -1;
    } else if (existCollect != null && existCollect.getIsDelete() == 1) {
        // 之前取消过 -> 重新收藏 ✅
        existCollect.setIsDelete(0);
        articleCollectMapper.updateById(existCollect);
        collectChange = 1;
    } else {
        // 首次收藏 ✅
        articleCollectMapper.insert(collect);
        collectChange = 1;
    }
    
    // 更新收藏数
    articleMapper.incrementCollectCount(articleId, collectChange);
    
    // 返回新状态和收藏总数
    return new CollectResult(newCollectStatus, currentCollectCount);
}
```

## 🔄 新的工作流程

### 用户操作流程

1. **首次点击收藏按钮**:
   - 请求: `POST /article/collect?articleId=1`
   - 响应: `{ collected: true, collectCount: 101 }`
   - 前端: 按钮变为"已收藏"，显示"101人收藏"

2. **再次点击（取消收藏）**:
   - 请求: `POST /article/collect?articleId=1`
   - 响应: `{ collected: false, collectCount: 100 }`
   - 前端: 按钮变为"收藏"，显示"100人收藏"

3. **第三次点击（重新收藏）**:
   - 请求: `POST /article/collect?articleId=1`
   - 响应: `{ collected: true, collectCount: 101 }`
   - 前端: 按钮变为"已收藏"，显示"101人收藏"

### 数据库操作

| 操作 | article_collect表 | article表 | Redis缓存 |
|------|------------------|-----------|-----------|
| 首次收藏 | INSERT (isDelete=0) | collectCount +1 | collected: true |
| 取消收藏 | UPDATE isDelete=1 | collectCount -1 | collected: false |
| 重新收藏 | UPDATE isDelete=0 | collectCount +1 | collected: true |

## 🎨 前端使用示例

### Vue 3 示例

```vue
<template>
  <button @click="handleCollect" :class="{ collected: isCollected }">
    {{ isCollected ? '已收藏' : '收藏' }}
    <span class="count">{{ collectCount }}</span>
  </button>
</template>

<script setup>
import { ref } from 'vue'
import { collectArticle } from '@/api/articleController'

const isCollected = ref(false)
const collectCount = ref(0)

const handleCollect = async () => {
  try {
    const res = await collectArticle({ articleId: props.articleId })
    if (res.data.code === 0) {
      isCollected.value = res.data.data.collected
      collectCount.value = res.data.data.collectCount
      
      const msg = isCollected.value ? '收藏成功' : '已取消收藏'
      message.success(msg)
    }
  } catch (error) {
    message.error('操作失败')
  }
}
</script>
```

## ⚠️ 注意事项

### 1. 保留取消收藏接口

虽然现在收藏接口可以切换状态，但保留 `/collect/cancel` 接口以保持向后兼容：

```java
@PostMapping("/collect/cancel")
public BaseResponse<Boolean> cancelCollectArticle(@RequestParam Long articleId,
                                                   HttpServletRequest httpRequest) {
    // 调用收藏接口，如果已收藏则会自动取消
    CollectResult result = articleService.collectArticle(articleId, loginUser.getId());
    return ResultUtils.success(!result.getCollected()); // 返回是否成功取消
}
```

### 2. Redis 缓存更新

每次切换收藏状态时，都会更新Redis缓存：

```java
String collectKey = ARTICLE_COLLECT_KEY_PREFIX + articleId;
redisTemplate.opsForHash().put(collectKey, userId.toString(), newCollectStatus);
```

### 3. 并发控制

使用数据库事务保证数据一致性：

```java
@Transactional(rollbackFor = Exception.class)
public CollectResult collectArticle(Long articleId, Long userId) {
    // 事务保证原子性
}
```
