# 无限级评论功能实现说明

## 📋 概述

本次升级将评论功能从**二级评论**（主评论 + 回复）升级为**无限级评论**，支持在任意评论下继续回复。

## 🔄 核心改动

### 1. 数据库设计

#### 新增字段

```sql
-- rootId: 根评论ID，所有回复都指向同一个主评论
ALTER TABLE `comment` ADD COLUMN `rootId` bigint DEFAULT NULL;

-- replyToUserId: 被回复的用户ID，用于显示 @用户名
ALTER TABLE `comment` ADD COLUMN `replyToUserId` bigint DEFAULT NULL;
```

#### 字段说明

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | bigint | 评论ID | 1001 |
| `parentId` | bigint | 父评论ID | null(主评论) / 1001(回复) |
| `rootId` | bigint | 根评论ID | null(主评论) / 1001(所有回复) |
| `replyToUserId` | bigint | 被回复的用户ID | 用于显示 @用户名 |

#### 评论层级示例

```
主评论 (id=1001, parentId=null, rootId=null)
├─ 回复1 (id=1002, parentId=1001, rootId=1001, replyToUserId=用户A)
│  └─ 回复1-1 (id=1003, parentId=1002, rootId=1001, replyToUserId=用户B)
│     └─ 回复1-1-1 (id=1004, parentId=1003, rootId=1001, replyToUserId=用户C)
└─ 回复2 (id=1005, parentId=1001, rootId=1001, replyToUserId=用户A)
   └─ 回复2-1 (id=1006, parentId=1005, rootId=1001, replyToUserId=用户D)
```

**关键点**：
- 所有回复的 `rootId` 都指向主评论的 `id`
- `parentId` 指向直接父评论
- `replyToUserId` 指向被回复的用户

### 2. 后端实现

#### CommentServiceImpl 核心逻辑

```java
// 添加评论时设置 rootId 和 replyToUserId
if (request.getParentId() != null) {
    Comment parentComment = commentMapper.selectById(request.getParentId());
    
    // 设置 rootId：如果父评论是主评论，rootId = 父评论ID；否则 rootId = 父评论的rootId
    rootId = parentComment.getRootId() != null 
        ? parentComment.getRootId() 
        : parentComment.getId();
    
    // 设置被回复的用户ID
    replyToUserId = parentComment.getUserId();
    
    // 增加根评论的回复数
    commentMapper.incrementReplyCount(rootId, 1);
}
```

#### 查询优化

```java
// 使用 rootId 查询所有回复
@Select("SELECT c.*, u.userName, u.userAvatar, u2.userName as replyToUserName " +
        "FROM comment c " +
        "LEFT JOIN user u ON c.userId = u.id " +
        "LEFT JOIN user u2 ON c.replyToUserId = u2.id " +
        "WHERE c.rootId = #{rootId} " +
        "AND c.isDelete = 0 " +
        "AND c.auditStatus = 'APPROVED' " +
        "ORDER BY c.createTime ASC")
List<Comment> selectRepliesByRootId(@Param("rootId") Long rootId);
```

## 📊 数据迁移

升级脚本会自动迁移现有数据：

```sql
-- 更新现有回复的 rootId
UPDATE `comment` c1
LEFT JOIN `comment` c2 ON c1.parentId = c2.id
SET c1.rootId = CASE 
    WHEN c2.parentId IS NULL THEN c2.id  -- 父评论是主评论
    ELSE c2.rootId                        -- 父评论是回复
END
WHERE c1.parentId IS NOT NULL;
```

## ✅ 功能验证

### 测试场景

1. **添加主评论**
   - parentId = null
   - rootId = null
   - replyToUserId = null

2. **添加二级回复**
   - parentId = 主评论ID
   - rootId = 主评论ID
   - replyToUserId = 主评论用户ID
   - 显示：`@主评论用户 回复内容`

3. **添加三级回复**
   - parentId = 二级回复ID
   - rootId = 主评论ID
   - replyToUserId = 二级回复用户ID
   - 显示：`@二级回复用户 回复内容`

4. **添加N级回复**
   - parentId = 上一级回复ID
   - rootId = 主评论ID（始终不变）
   - replyToUserId = 上一级回复用户ID
   - 显示：`@上一级回复用户 回复内容`

### 验证点

- ✅ 可以在任意回复下继续回复
- ✅ 显示 `@用户名` 格式
- ✅ 回复数统计正确（统计在根评论上）
- ✅ 删除回复时正确减少回复数
- ✅ 点赞功能正常
- ✅ 删除功能正常

## 🎯 优势

### 相比二级评论的改进

1. **用户体验**
   - 支持深度讨论
   - 清晰的回复关系（@用户名）
   - 更自然的对话流程

2. **数据结构**
   - 使用 `rootId` 统一管理所有回复
   - 查询效率高（一次查询获取所有回复）
   - 回复数统计准确

3. **扩展性**
   - 支持任意深度的评论
   - 便于实现评论折叠/展开
   - 便于实现评论排序

## 📝 注意事项

1. **性能优化**
   - 已添加 `rootId` 索引
   - 前端只展示前3条回复，点击"查看更多"加载全部
   - 考虑对超长评论链进行分页

2. **数据一致性**
   - 删除主评论时，所有子回复也会被删除（逻辑删除）
   - 回复数统计始终在根评论上

3. **前端展示**
   - 使用 `@用户名` 格式清晰标识回复关系
   - 蓝色高亮显示被回复的用户名
   - 保持良好的视觉层级
